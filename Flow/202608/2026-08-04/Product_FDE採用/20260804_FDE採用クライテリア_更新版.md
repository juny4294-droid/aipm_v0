# 0. 採用活動を踏まえた更新サマリ（2026-08-04）

**目標（採用定例より）**: FDE要件を見極めつつ、**11月までに1名採用**（8月中の内定受諾がベスト）

### クライテリアの方針転換（重要）

これまでFDE Mustの重心は **顧客折衝・課題発見・解決提案** だった。  
CSで病院SE出身（現場折衝・課題抽出が強い）が内定したことで、その領域は **CS側にかなり任せられる見込み**。

→ **FDEの見極めは技術力（設計・実装・データ/システム制約の突破）寄りに少しシフト**してよい。  
ただしゼロにするわけではない。CSと組んで現場に入れること、やりきり（Passion/Grit）は引き続き必須。

| 観点 | これまでの重心 | これからの重心（案） |
|------|---------------|---------------------|
| 顧客折衝・現場調整 | FDE Must寄り | **CS主導＋FDE協働**（FDE単体のMustは緩めてよい） |
| 課題発見・抽出 | FDE Must寄り | **CSと共同**（FDEは構造化・技術論点への翻訳を重視） |
| 解決提案（業務寄り） | FDE Must寄り | CS/PSと分担。FDEは **実装可能な解への落とし込み** |
| 技術（設計・実装・データ連携） | Mustだが相対的に後ろ | **FDEの主戦場として前面に** |
| Passion / Grit | 二次 Must | **維持**（困難耐性は技術シフト後も必須） |

### これまでの結果から固まった見極め

| 学び | 内容 |
|------|------|
| **CS補完でFDEを技術寄りにシフト可** | 病院SE出身のCS内定により、現場折衝・課題抽出はCSに厚みが出る。FDEは技術力（＋CS協働）を優先してよい |
| **二次のMustは Passion（やりきり／Grit）** | 三宅様二次のTake away。「やりきり・馬力・自ら顧客に行く」が最も効く。Growthは Nice to Have |
| **Capabilityだけでは通さない** | 津村様は一次通過→二次見送り。スキル・経験幅があっても Trust（帰属・任せ方）と役割期待のズレで落とす |
| **綺麗な環境だけでは足りない** | 明賀様二次後すり合わせ。データの不備・理不尽な状況でも逃げずにやり抜けるかを最終で確認する |
| **FDEの役割定義を明示する** | 「顧客対応役」だけか、「業務フロー改善＋Tech Lead補佐」も含むかで適否が変わる。後者＋技術寄りならポテンシャル型も通しやすい |
| **パターンC"/VPは慎重（FDEとして）** | 業務委託歴中心・自己評価過大・帰属意識の弱さがある場合、正社員リーダ/VPはリスク |
| **活躍の2層** | ①最初からリーダー候補　②若手プレイヤーで伸ばす。プレイヤー見込みなら若手でないと伸びにくい |
| **採用ポートフォリオ** | **CS（現場折衝・課題抽出）× FDE（技術実装・やりきり）× Tech Lead/VP（アーキ・品質）** の三層。FDEとTLは別枠で並行 |
| **スカウト注力像** | FDEは技術力＋やりきりのバランスを優先。顧客折衝の深さはCS補完を前提に相対低下してよい |
| **要件再検討トリガー** | 二次を8/17前後まで回し、通過が極端に少ない場合はFDE要件を再検討（技術シフト後の通過率も見て判断） |

### 選考フローの現在版（更新）

- **一次** = Capability — **技術・実装・制約突破を厚めに**（課題構造化は見るが、顧客折衝の深掘りは相対的に軽くてよい）
- **二次** = **Trust / Passion**（一緒に働きたいか・任せられるか・やり切れるか）＋転職軸マッチ＋**CSとの協働イメージ**
- **最終** = Visionary / 条件 ＋ **役割期待のすり合わせ**（困難な側面を伝えたうえで耐性・志望を確認）
- ~~二次で Growth を Must で見る~~ → **Growth は補助（Nice）**

# 1. 人材像

- CS/PSと**同じテーブル**で顧客課題に入り、**技術側の主担当として設計 → 実装 → 効果確認 → 改善**までやり切れる人。
- 現場折衝・一次の課題抽出は **CS（病院現場理解が厚い人材）と分担**してよい。FDEはそれを受けて構造化し、実装可能な解に落とす。
- **1人目FDE**として、組織づくり・組織のマインドづくりを推進できる人。
- 綺麗な要件だけではない。**データ不備・現場の理不尽・調整コスト**がある前提でも前に進める人。

### FDEに求めるもの（技術シフト版）

**役割**

| 区分 | 内容 | 備考 |

**採用への示唆**

- いま採る1人目FDEは「PdM待ち・TL待ち」ではなく、**初期は広い責務を自走する前提**で説明する（最終面接で明示）。
- ただし **顧客課題の発見・現場折衝**は、表上FDEでも、実態は **CS（病院SE出身など）との共同**で厚くできる。説明時は「FDE単独で全部」と誤解させない。
- アーキ・品質・組織方向性から逆算する仕事は **Tech Lead / VPクラスを別枠で確保**する。
- FDEの説明は「顧客対応役」に寄せすぎない。**技術実装・データ連携・制約突破**を主戦場とし、課題発見はCSと組む姿を伝える。

# 2. 面接の判断

**何を重点的に見るか（2026-08-04 更新・技術シフト版）**

- 一次 = **Capability（技術寄り）** — 設計・実装・データ/システム制約の突破を実例1件で深掘り。課題の「発見」より「構造化→実装可能な解」
- 二次 = **Trust / Passion** — 一緒に働きたいか・任せられるか・やり切れるか。顧客折衝の主役経験より、**CSと組んで現場に入れるか／困難を逃げないか**
- 最終 = **Visionary / 条件** — 一緒に挑戦したいか＋**CS協働前提の役割すり合わせ**
- **Growth** は二次の Must ではない（Nice / 補助）

**二次で特に見る Passion / Grit のサイン**

- 強い: しんどい局面（汚いデータ、制約、理不尽）でも届け切った具体例。キャッチアップが深い。CS/現場と組んで前に進める
- 懸念: 馬力・モチベーションが弱い／承認待ち／技術課題から逃げる／綺麗な条件でないと動けない

**最終で特に確認すること**

- FDEの働き方を具体資料で説明したうえで、「データの不備・理不尽な状況」などの困難側面を隠さず伝える
- **CSが現場折衝・課題抽出を厚く担う前提**でも、技術主担当としてやり切れるかを確認する
- FDEを「顧客対応のみ」と誤解していないか。技術実装＋業務改善／TL補佐寄りの期待も含めてすり合わせる
- 面接官間（吉田含む）で期待値を揃えたうえで判断する
