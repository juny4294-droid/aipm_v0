## 採用目的

エンジニア組織が顧客と直接会話しないことで、品質低下・スピード鈍化が起きている。顧客課題を直接ヒアリングし、技術的解決を自ら立案・推進できるエンジニア(= FDE) を置く。

理想像（長期）:

> Biz/マネジメント/エンジニアの境界をなくし、初期接点から解決策提供までを一つのチームで完結させ、組織間コミュニケーションコスト、ロスが最小のプロダクト組織となる。

## いま起きているズレ

| ズレ | 内容 |
|------|------|
| アトラクトが曖昧 | 「新規0→1」「AIDPCスケール」「CS協働の技術主担当」など、候補者への期待が面接ごとに揺れる |
| 見極めの軸が二極 | 「顧客接点の強さ」優先 vs 「エンジニアリング必須」— どちらを落とすかの基準が揃っていない |
| 短期と長期の相反 | 8/4は「CS補完で技術シフト」としたが、理想像は顧客接点を強く含む。短期の見極めと長期の理想が混線しやすい |
| 個別候補の摩擦 | 例: 別所様（PdM強・実装弱）— 顧客課題解決力は高いが、技術Mustに届くか／AIDPC運用適性か |

→ **「理想のFDE」と「いま採る1人目に必須なこと」を分けて書く**

# 3. 議論の論点

## 論点A — FDEの目的（1文）

たたき台:

> 顧客課題を現場で捉え、技術で解を設計・実装し、効果まで届けることで、顧客へ価値を届ける。

代替案:

- A1: 顧客との距離を縮め、品質とスピードの低下を止める（組織課題起点）
- A2: 顧客業務フローを変えるプロダクト開発を、CS要求を起点に最適に行う
- A3: プロダクト価値の「高さ」を上げ、foroが維持する「期間」と役割分担する

## 論点B — 技術の最低ライン

顧客課題に対して技術的アプローチで解決策を検討提案できる。  
ハイレベル（自身一人で対応不可能）な機能構築についてもテックリードサポートの元で対応可能。

| 技術L | 定義 | 判定 |
|--------|------|------|
| 技術L0 | 実装経験なし | 不可 |
| 技術L1 | 自身で設計はできるが、実装経験がほぼない | **不可?** |
| 技術L2 | 自分で設計・実装できるが、TLとの議論は受け身 | must下限 |
| 技術L3 | TLと要求・制約・トレードオフを議論し、実装方針を決められる | 適正レベル |
| 技術L4 | アーキ・品質を主導できる | Nice / TL別枠寄り |

1人目のMust下限は 技術L2？ 技術L1＋強い顧客力は通すか？

## 論点C — 顧客接点のMust度

| 顧客L | 定義 | 8/4版との関係 |
|--------|------|---------------|
| 顧客L0 | 顧客に出ない／出たくない | 不可 |
| 顧客L1 | CS主導の場に入り、技術論点を言語化できる | 8/4 Must相当 |
| 顧客L2 | 自ら顧客と対話し、理想業務と現状ギャップを主導できる | 7/7 Must相当 |
| 顧客L3 | FS/CS境界まで含み、初期接点から完結できる | 理想像（チーム成熟後） |

いまの1人目は 顧客L1必須＋顧客L2 Nice か、顧客L2必須か？

## 論点D — アトラクトの統一

| OK（約束してよい） | NG（期待させすぎ） |
|-------------------|-------------------|
| 顧客課題に技術で入り、実装までやり切る | 「新規0→1だけ」「受託のPMだけ」 |
| AIDPC等の探索で価値の高さを上げる | 「IF調整・保守だけ」が主業務 |
| CS/FSと分担しつつ、境界を減らしていく | 「入社直後から境界をなくす」 |
| 技術は議論できる水準が必須（キャッチアップ前提でも可） | 「コードは書かなくてよい」 |

# 4. 更新版クライテリア（たたき台）

## 人材像（1人目）

- 顧客課題を技術で解く主担当として、設計→実装→検証→改善までやり切れる
- 顧客接点は少なくとも 顧客L1。理想は 顧客L2
- 技術は 技術L2 が最低ライン?
- データ不備・現場の理不尽があっても前に進める（Grit）

## 役割 Must / Nice

| 区分 | 内容 |
|------|------|
| Must | 実運用前提の業務設計・データ設計（業務フロー＋データフロー） |
| Must | 実装→検証→改善まで自走（技術L2以上） |
| Must | CS/現場と協働し、技術論点・制約・実現方法を言語化して前に進める（顧客L1以上） |
| Must | 困難・非効率でも逃げずにやり切る（Grit） |
| Nice | 自ら顧客と対話し、理想業務と現状ギャップを主導（顧客L2） |
| Nice | 0→1立ち上げ／安定運用まで改善／FDEチームのリード・型づくり |

## 落とす基準

| ケース | 判断（案） |
|--------|------------|
| 顧客力強い × 技術L0〜技術L1 | **見送り** |
| 技術L2以上 × 顧客L0 | **見送り** |
| 技術L1 × 顧客L2 × 学習意欲が極めて高い | **要議論**（90日技術マイルストーン必須） |
| 0→1のみ希望で泥臭い実装をやりたくない | **見送り** |
