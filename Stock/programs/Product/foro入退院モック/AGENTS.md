# foro入退院モックの作り方

Cursor 以外のエージェントでも、このファイルを最初に読んで同じ手順で進める。実装リポジトリは編集しない。

## このフォルダ

| ファイル | 役割 |
|---|---|
| [README.md](README.md) | 人向けの説明 |
| [AGENTS.md](AGENTS.md) | この手順 |
| [current.html](current.html) | 現行画面の動く控え。編集しない |
| [screens.md](screens.md) | 現行画面でできること |
| [sources.md](sources.md) | 写した元の場所。キットを最新に合わせるときだけ読む |

## 仕様の読み方

頼まれ方は、次の形が通常である。

「書いた仕様のリンクを元に、入退院のモックを作って」

仕様は Notion など、このフォルダの外に書いてある。渡されたリンクの中身を読み、そこにある画面変更だけをモックにする。仕様をこのフォルダへ写さない。チャット用に書き直させない。

リンクの中身を取得できないときは、本文の貼り付けを頼む。取得できるまでモックを作らない。

仕様に書いていない必須、権限、空のときの動きは決めない。モックでは未決定と分かる置き方にし、成果物の `参照.md` に残す。

## 作業の前に

[screens.md](screens.md) と [current.html](current.html) を読む。相談一覧はステータスのタブと全項目フォームがある。短い旧フォームに戻さない。

色、余白、部品は `current.html` の CSS 変数と、`.btn` `.badge` `.field` `.card` を使う。別のデザインにしない。

現行と食い違うと感じても、想像で画面を足さない。実装リポジトリが手元にあるときだけ [sources.md](sources.md) のファイルを見て、コピーした `mock.html` 側を合わせる。手元にないときは `current.html` と `screens.md` を正とする。

## 成果物の置き場所

ユーザーがフォルダを指定したら、そこへ出す。指定がなければ、このフォルダの隣に次を作る。

`モック/<短い名前>/`

中身は次の2つ。

- `mock.html` … `current.html` のコピーを、仕様の画面変更だけ直したもの
- `参照.md` … 仕様のリンクと、モックに置かなかったこと。仕様の写しではない

同じ会話で直しが続いたら、新しいフォルダは作らず、その2つを更新する。仕様のリンクが更新されていたら、読み直してから直す。

## モックの直し方

1. `current.html` を `mock.html` にコピーする。`current.html` は編集しない。
2. 仕様に書いてある画面変更だけを反映する。相談一覧、サイドピーク、新規登録、ダッシュボードの、仕様にない動きは残す。
3. 足した要素に `is-new` を付ける。`#delta-note` の `hidden` を外す。
4. 検索、絞り込み、行を開く、登録、保存は、コピー後もクリックして動くようにする。
5. データは架空のまま。実在の患者や病院名を足さない。
6. 新しい画面は左ナビに項目を足し、`setPage` と同じ切り替えに載せる。

## 参照.md

仕様の代わりではない。どの仕様からモックを作ったかと、仕様どおりに置けなかったことだけを書く。

```markdown
# モック

> 仕様: <渡されたリンク>
> モック: [mock.html](mock.html)
> 作成日: YYYY-MM-DD

## 仕様にあってモックに置いていないこと

## 未決定
```

該当がなければ、見出しの下に「なし」と書く。
