# 入退室のアカウント設定

更新: 2026-10-28

foro CRM に入る人・出る人のアカウント作業。人ごとの進捗は同じフォルダに `YYYYMMDD_氏名.md` で残す。チェックの元は Notion [チーム参画退職管理](https://app.notion.com/p/efce12da768f4c809bfa91c42b3d6c7a)。

招待URLや一時パスワードは書かない。Notion の本人ページを見る。

## 入るとき

メールアドレスが決まってから付ける。Corporate 依頼が先のものがある。

### Corporate に依頼する

- [ ] メールアドレス（`名.姓@medup.jp`）
- [ ] Slack
- [ ] Notion
- [ ] Microsoft 365（Azure 招待の前に必要）

### こちらで招待・権限付与する

- [ ] GitHub: 既存アカウントをもらうか、新規を作ってもらい共有してもらう
- [ ] [Figma](https://www.figma.com/files/team/887256984732684701/Medup/members?fuid=1091545821782031404): 閲覧のみ
- [ ] GCP [analytics-tool](https://console.cloud.google.com/iam-admin/iam?hl=ja&project=analytics-tool-206405)（`analytics-tool-206405`）
  - 編集者
  - Secret Manager のシークレット アクセサー
  - BigQuery 管理者
- [ ] GCP [medical-institution-service](https://console.cloud.google.com/iam-admin/iam?hl=ja&project=medical-institution-service)（キックオフ上の呼び名は medup-foro）
  - 編集者
  - Secret Manager のシークレット アクセサー
  - AlloyDB データベース ユーザー
  - Service Usage ユーザー
- [ ] GCP: refery、foro-crm-ui-storybook、foro-outpatient-web-storybook、refery-storybook、medup-data-platform
  - 編集者
  - Secret Manager のシークレット アクセサー
- [ ] AlloyDB に Cloud IAM のアカウントを作る。本番クラスタは [medup-foro-alloydb-kms-prd](https://console.cloud.google.com/alloydb/locations/asia-northeast1/clusters/medup-foro-alloydb-kms-prd/users?project=medup-foro)（プロジェクト `medup-foro`）。旧名 `medup-foro-alloydb-prd` は無い。開発者のデータベースロールは `developer_group`、データOps は `dataops_group`。DB 接続の続きは Notion の [本番DBアクセス可能にする設定](https://app.notion.com/p/2d51da5a7f3b80a9990beea29bc14a50)
- [ ] [1Password](https://medupinc.1password.com/people): 招待し、認証後に foro CRM グループへ追加
- [ ] [Sentry](https://medup.sentry.io/settings/members/): メンバー
- [ ] [Redash](https://data-mgmt.medup.jp/users?order=-created_at&page=1&page_size=20): 招待URLは本人の Notion ページ
- [ ] Azure: M365 ができてから各環境へ招待
- [ ] resend
- [ ] foro ステージング / foro 本番
- [ ] foro_stg.medup_foro_admins / foro_prd.medup_foro_admins
- [ ] refery ステージング / refery 本番

SendGrid は共通アカウントなので、個人招待はしない。

### 渡しもの

キックオフページの「最初のタスク」「開発の流れ」「Slack チャンネル」「ドメイン知識」は、アカウント作業とは分けて Notion 側で渡す。

## 出るとき

付与したものを外す。付与していないものは対象外とログに書く。

Corporate に依頼する。

- [ ] メールアドレス
- [ ] Slack
- [ ] Notion
- [ ] medup.jp の組織管理者に相当するアカウント

こちらで外す。

- [ ] GitHub: チームから外し、member に下げる。Organization からも外す
- [ ] Figma
- [ ] GCP の IAM（analytics-tool、medup-foro、medical-institution-service、medup-data-platform、refery、各 storybook。付与していれば medup-core-service、medup-prototypes、medup-foro-kms も）
- [ ] AlloyDB の Cloud IAM
- [ ] Azure
- [ ] 1Password（先に suspend してから削除してよい）
- [ ] Sentry
- [ ] Redash を無効化
- [ ] GitGuardian（先に deactivate してから削除してよい）
- [ ] Resend
- [ ] foro ステージング / 本番
- [ ] foro_stg.medup_foro_admins / foro_prd.medup_foro_admins

SendGrid は共通アカウントなので、個人削除はしない。

## ログの残し方

1. `documents/4_executing/YYYYMMDD_氏名.md` を作る
2. メールアドレス、入る日または出る日、Notion の本人ページを書く
3. 作業した時刻、対象サービス、付けた権限または外した範囲、依頼先、止まった理由を追記する
4. この README の手順一覧のリンクに、そのファイルを足す
