# アップロード処理の変更概要

整理日: 2026-10-23

仕様: [仕様書](仕様書.md)  
画面: [mock.html](mock.html)

患者番号の復号は、ブラウザでも保存先のファイルでも行わない。インポート要求に「復号する」を乗せ、data-management-api がファイルを読んだ直後、患者番号を取り出す前にルールを適用する。

## いまの処理

1. 入院タブの「インポート」で、様式1（必須）とDファイル（任意）を選ぶ。
2. admin-web が署名付きURLを取り、選んだファイルをそのままアップロードする。
3. admin API が取り込みログを作り、data-management-api に次を渡す。
   - 取り込みID、テナントID
   - 様式1のファイル名とURL
   - Dファイルのファイル名とURL（あるときだけ）
4. data-management-api がファイルを読む。
   - 様式1は17列。2列目が患者番号。先頭行の1列目が数字でなければヘッダとして除く。
   - Dファイルは30列。2列目が患者番号。ヘッダの判定は様式1と同じ。
5. 入院レコードを作り、入院紹介を更新する。紐づけのキーは、患者番号の先頭の0と空白を除いた値である。

復号の指定はない。上げたファイルの2列目が、そのまま患者番号になる。

## 変えるところ

インポート要求に `decrypt`（真偽値）を足す。admin-web から admin API を経由し、data-management-api まで渡す。

| 値 | 処理 |
|---|---|
| `true` | ヘッダを除いた各行の、ルールが指定する列に、そのテナントのルールを適用してから既存の取り込みに進む |
| `false` | いまと同じ。列は変えない |
| 項目なし | `false` として扱う。いまの呼び出し元の動きは変えない |

画面でルールがあるテナントの初期値は「復号する」なので、新しい画面は `true` を送る。ルールがないテナントの画面は選択を出さず、`false` を送る。

`true` なのにそのテナントのルールがないときは、取り込みを失敗させる。匿名化ファイルをそのまま登録しない。

適用の位置は、列数のチェックとヘッダ除去のあと、患者番号をレコードに載せる前である。先頭の0を除く処理より前に行う。先に先頭の0を除くと、有明の「同じ桁数まで0埋め」が別の番号になる。例は `0079252330` を先に `79252330` にしてから復号すると、`0007925233` に戻らない。

様式1とDファイルがあるときは、両方に同じ `decrypt` を適用する。Dファイルがないときは様式1だけに適用する。Dファイルを必須にはしない。

保存してあるファイル自体は書き換えない。復号結果は、この取り込みで作る入院レコードの患者番号にだけ反映する。
