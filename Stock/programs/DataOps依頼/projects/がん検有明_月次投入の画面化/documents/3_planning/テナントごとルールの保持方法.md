# テナントごとルールの保持方法

整理日: 2026-10-23

仕様: [仕様書](仕様書.md)

復号ルールは、テナント1件につき1行で data_ops に持つ。画面からの追加や編集はしない。アルゴリズムの実体はコードに置き、行はそのどれを使うかを指す。

## テーブル

`data_ops` に `hospital_admission_patient_number_rules` を置く。置き場所は、入院投入の初期設定で使っている `tenant_medical_institution_code_ids` と同じデータベースである。

| 列 | 内容 |
|---|---|
| id | UUID |
| tenant_id | テナントID。一意 |
| rule_code | コード側の関数名 |
| id_column | 患者番号の列。1始まり。有明は `2` |
| created_at / updated_at | 作成・更新日時 |

行がないテナントはルールなしとする。入院タブは選択を出さず、ファイルをそのまま取り込む。

行があるテナントは、インポートのモーダルに「復号する／しない」を出す。画面が行の有無を知るため、既存の入院インポート可否の応答に、ルールがあるかどうかの真偽値を足す。ルールの中身は画面に返さない。

## 有明のルール

最初の1行はテナント `204`。

| 列 | 値 |
|---|---|
| rule_code | `strip_trailing_zero_and_pad` |
| id_column | `2` |

この関数は次のとおり。

- 空、または末尾が `0` でない値は変えない
- 末尾が `0` の値は、末尾の1文字を除き、元の桁数になるまで先頭を0埋めする
- 例: `0079252330` → `0007925233`、`0000201310` → `0000020131`

様式1とDファイルのどちらも、この列に同じ関数をかける。

## ルールを足すとき

新しい変換式が必要なときは、コードに関数を足し、`rule_code` を増やす。すでに関数があるテナントへ割り当てるときは、行を1件入れる。どちらも今回の管理画面では行わない。

入院の別経路にある、テナント番号で分岐した減算（テナント 78、91、34）は、このテーブルに移さない。対象は、今回の入院タブのインポートで選んで適用するルールだけである。
