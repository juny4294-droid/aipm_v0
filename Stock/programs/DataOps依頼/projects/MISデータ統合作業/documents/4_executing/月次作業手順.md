# MIS月次作業手順

2026-10-27 の実施に合わせた手元の手順。流れの正本は [20260818_MIS月次作業](https://app.notion.com/p/3c01da5a7f3b80779567c2e9ca944fc1)。重複の統合は [統合作業手順](../3_planning/統合作業手順.md)。

作業ディレクトリは `data-customer-ops/update-mis/`。DB トンネルはポート 5434。`src/credentials/mhlw.json` のトークンは約1時間で切れるので、切れたら `gcloud auth print-access-token` で入れ直す。

## 1. ファイルを置く

Drive の [厚生局データ](https://drive.google.com/drive/folders/1-BeEQGktTthtjLwd6_FZNMFw-gkr1bJe) から、対象月の一覧・新規・閉院相当を取る。`data/YYYYMM/` の直下にフラットで置く。医科・歯科の施設一覧、新規（遡及を含む）、廃止・辞退・取消が揃っていること。

## 2. 変換する

```bash
pipenv run extract-overview data/YYYYMM
pipenv run extract-new data/YYYYMM
pipenv run extract-closed data/YYYYMM
```

出力は `src/output/` の3つの CSV。医療機関コードの欠けと、新規・廃止の 255 字超えを見てから管理画面へ出す。一覧の `病床/診療科` が 255 字を超えていても、アップロード自体は通ることがある（202610 は 5 件で 200）。

## 3. 管理画面で取り込む

[MIS管理画面](https://admin-web.medup-core-service.com/mhlw-sync-works) で、新規、閉院、情報更新、一覧アップロード、一覧のみ、MISのみ、差分の順に取り込む。成功は 204（一覧アップロードは 200）。

情報更新を二度押すと、2回目は 400 `AlreadyImported` になる。画面のトーストは失敗と出るが、1回目が 204 なら取り込み済み。

差分取り込みで重複になったときは、アーカイブ済みの行に医療機関コードが残っていないかを見る。202609 は `53160`（コード `2313000487`）と `156062`（コード `3910119738`）がこれだった。新規登録の重複 `40178` / `404403` / `402482` は INSERT 不要として、`mis_prd.mhlw_sync_work_insert_records` から削除して取り込み直した。

## 4. 重複を統合する

詳細は統合作業手順。届け出まちは統合しない。

1. `python src/generate_merge_sql.py data/YYYYMM` で候補を出す。SQL は実行されない。
2. 全ペアの寄せる側と残す側の ID を、Redash の foro [2191](https://data-mgmt.medup.jp/queries/2191) と data_ops [2287](https://data-mgmt.medup.jp/queries/2287) に入れて結果を取る。クエリは書き換えない。保存もしない。API は Cloudflare に弾かれるので、ブラウザで実行して CSV を `output/merge_sql/redash_YYYYMMDD.json` にする。0件の ID も `ids` に入れる。
3. `--redash-json` を付けてもう一度生成する。スクリプトが数えた `communications` / `referrals` / `medical_institution_mappings` / `referral_masters` が Redash と一致することを確かめる。
4. `tasks` は要チェックになっても単純 UPDATE なので移してよい。
5. 確認シートを作り、試し流しの件数が一致したペアを `--commit` する。`tasks`、`medical_institution_attachment_files`、`medical_institution_label_values` は `jun.yamada` に権限が無く、そのテーブルを含むペアはスクリプトが全体を止める。そのペアは `SET ROLE postgres` で、件数を確認してから同じ UPDATE を流す。終わったら `RESET ROLE`。
6. 関連レコードが 0 のペアは SQL が無い。画面でアーカイブする。

202610 は候補 27、重複 9、届け出まち 18。重複 9 件は統合してアーカイブ済み。

## 5. アーカイブして確認する

SQL のあと、管理画面で寄せる側をアーカイブし、医療機関コードを `0` にする。残す側の ID と 10 桁コードは変えない。`mis_archive.sql` は流さない。

確認は `mis_prd.medical_institutions` と、移したテーブルの件数。

- 寄せた側は `archived`、コードは `0`。
- 残す側は `open` のまま、10 桁コードが付いている。
- 移したテーブルでは、寄せた側が 0 件。残す側は移した件数だけ増えている。
- エリアラベル（component_type 6）は寄せた側に残る。それ以外が残っていたら止めて見る。
