ユーザーデータを投入したときに作業完了通知メールを送る相手先メアドをTBLで管理している。
組織変更等で担当変更があったときに随時SQLで更新を行なっている。

- 担当から除外：論理削除
- 担当追加：insert

宛先の順番は `"order"` で制御する。

入力は CS 提示のスプレッドシート。シートは「削除対象」と「新規追加」。

- [送信先スプレッドシート](https://docs.google.com/spreadsheets/d/171mV_B6Pyqyv1t3Y1UEex-9pf-t8VCkNJIq_egBnjg0/edit?gid=0#gid=0)

2026-10-01 に実行した SQL そのものは [実施記録](20261001_実施記録.md)。

## 対象TBL

- data_ops_prd `public.completion_notification_users`

## カラム

| カラム | 内容 |
|---|---|
| id | UUID。unique。insert 時は `gen_random_uuid()` |
| tenant_id | テナントID |
| name | 氏名 |
| honorific | 敬称（例: 様） |
| email | メールアドレス |
| enabled_notification | boolean。`false` が論理削除。新規は `true` |
| last_sent_at | timestamp。not null。insert 時は `CURRENT_TIMESTAMP` |
| created_at | timestamp。insert 時は `CURRENT_TIMESTAMP` |
| updated_at | timestamp。insert 時は `CURRENT_TIMESTAMP` |
| "order" | 宛先の順番。予約語なのでダブルクォートで書く |

制約:

- 全項目 not null
- `tenant_id` + `email` が unique（`completion_notification_users_tenant_id_email_key`）

## 事前確認

1. 「新規」シートの中で、同じ `tenant_id` + `email` が複数行ないか見る。あるときは片方だけ残す。2026-10-01 は tenant 167 の `y-hase@teikyo-u.ac.jp` が「長谷山義勝 / order=1」と「長谷山 / order=2」の2行あったので、order=2 を insert から外した。
2. 既存行とぶつかる組がないか、insert 前に確認する。

```sql
SELECT tenant_id, email, "name", "order", enabled_notification
FROM public.completion_notification_users
WHERE (tenant_id, email) IN (
  (143, 'example@example.com')
);
```

既にある組は insert しない。2026-10-01 は tenant 143 / 藤本美生 / `Mio_Fujimoto@pref.hyogo.lg.jp` が既存で、unique 違反（23505）になった。

## 削除（論理削除）

「削除」シートの id に対して `enabled_notification` を `false` にする。行は消さない。

```sql
BEGIN;

UPDATE public.completion_notification_users
SET enabled_notification = false
WHERE id IN (
  '00000000-0000-0000-0000-000000000000'
);

SELECT id, enabled_notification
FROM public.completion_notification_users
WHERE id IN (
  '00000000-0000-0000-0000-000000000000'
);

-- COMMIT;
-- ROLLBACK;
```

2026-10-01 は 33件。SQL は [20261001_論理削除.sql](20261001_論理削除.sql)。

## 新規（insert）

全カラムを指定する。`"order"` はクォートする。メール末尾の空白は除く。

既存とぶつかっても全体を失敗させない場合は、末尾に `ON CONFLICT (tenant_id, email) DO NOTHING` を付ける。このとき既存行の name や `"order"` は更新されない。既存を書き換えたいときは別の UPDATE にする。

```sql
BEGIN;

INSERT INTO public.completion_notification_users
(id, tenant_id, "name", honorific, email, enabled_notification, last_sent_at, created_at, updated_at, "order")
VALUES
  (gen_random_uuid(), 0, '氏名', '様', 'example@example.com', true, CURRENT_TIMESTAMP, CURRENT_TIMESTAMP, CURRENT_TIMESTAMP, 1)
ON CONFLICT (tenant_id, email) DO NOTHING;

SELECT tenant_id, "name", honorific, email, "order", enabled_notification, created_at
FROM public.completion_notification_users
WHERE (tenant_id, email) IN (
  (0, 'example@example.com')
)
ORDER BY tenant_id, "order";

-- COMMIT;
-- ROLLBACK;
```

確認で見る件数には、`DO NOTHING` でスキップした既存行も含まれる。新規だけ見るときは `created_at` が実行時刻付近の行を見る。

2026-10-01 の insert は [20261001_新規insert.sql](20261001_新規insert.sql)。確認クエリは [20261001_insert確認.sql](20261001_insert確認.sql)。元データ 54件のうち、長谷山 order=2 は文から外し、藤本美生は `DO NOTHING` でスキップした。
