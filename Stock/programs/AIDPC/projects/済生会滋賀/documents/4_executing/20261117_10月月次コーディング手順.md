## 手順

ワンタイム変換でよい。変換スクリプトの Git 管理は不要。既存の出力があるときは上書きしない。

### 1. 患者番号を -1 する

対象は D / E / F / 様式1。2列目を数値化して 1 を引き、桁は戻す。出力名は元ファイル名の末尾に `_conveted` を付ける（ログ上の綴り。後続がこの名前を参照する）。

例: `0000001173` → `0000001172`

### 2. E と F を EF に統合する

入力は手順1の `En_..._2610_conveted.txt`（25列・CP932・ヘッダなし）と `Fn_..._2610_conveted.txt`（19列）。出力は UTF-8 BOM の TSV、31列（EF-1〜EF-31）。

- 結合キー: 施設コード + データ識別番号 + 退院年月日 + 入院年月日 + データ区分 + 順序番号
- 各キーで E 由来の明細番号 `000` を先に出し、その後に F 由来の `001` 以降
- F 行の明細点数・金額は、行為明細点数 + 行為明細薬剤料 + 行為明細材料料。整数は 8 桁ゼロ埋め、小数は小数3桁で 12 桁ゼロ埋め
- E は必ず 25 列で読む。24 列だと先頭がインデックス扱いになってずれる
- 結合キーは前後空白を除く
- 行数は E の行数 + F の行数

全文の列対応は [10月締](https://app.notion.com/p/40e1da5a7f3b8051a43df6f374693215) の「EFファイル」節。出力名は `EF_merged_251200194_2610.tsv`。

### 3. EF を Parquet にする

入力: 手順2の TSV  
出力: `apps/ai-dpc/patients/A001/monthly/ef_records/202610.parquet`  
`tenant_id` は全行 `A001`。

### 4. カルテ類を ehr_notes にする

6ファイルを1本にまとめる。出力: `apps/ai-dpc/patients/A001/monthly/ehr_notes/202610.parquet`

列順: `tenant_id`, `patient_id`, `note_datetime`, `note_title`, `text`, `dept_code`, `dept_name`, `note_category`, `source_file_name`, `converted_at`

- `tenant_id` は `A001`。`dept_code` は全行 NULL
- 患者番号は文字列のまま、先頭ゼロを残す
- 日時は Asia/Tokyo として読み、UTC の `timestamp[us]` にする。秒が無いものは 00 秒
- 本文は切らない。空欄でも行は残す（下記のスキップ以外）
- 重複排除しない

| 入力 | patient_id | dept_name | note_datetime | note_title | text | note_category |
|------|------------|-----------|---------------|------------|------|----------------|
| 医師記事 | 患者ID | 依頼科名称 | 記事記載日時 | 記事タイトル名称 | 記事内容 | 空 |
| 周産期 | 患者ID | 産科 | 陣痛発来日時と破水日時の遅い方。片方だけならその値。両方空ならその行だけ除外 | 周産期システム情報 | 要約・特記事項・異常の経過及び処置等 | 空 |
| 画像 | 患者ID | 依頼科 | 確定日時。空なら検査日時 | 検査種別 + `-` + 検査部位 | 所見 | 画像レポート所見 |
| 内視鏡 | 患者ID | 依頼科 | 検査日 + 検査時刻 | 検査項目 + `-` + 検査内容 | 検査目的・診断・検査機器・コメント・検体・手技を `#### 列名` 付きで連結 | 内視鏡情報 |
| 硝子体 | 患者番号 | 眼科 | 検査日時 | 硝子体手術病名 | 病名 | 空 |
| 入院診療計画 | 患者ID | 入院科 | 入院日付 | 入院診療計画書病名 | `入院時病名:` と `詳細:` | 空 |

日時が空でもなく、解釈にも失敗した行は埋めずに報告する。

### 5. 患者番号の桁を照合する

EF の患者番号と ehr_notes の患者番号で、先頭ゼロの有無が揃っているかを見る。値そのものは出さない。

### 6. D と様式1から cases を作る

入力は手順1の `Dn_..._2610_conveted.txt` と `FF1_..._2610_conveted.txt`。  
出力: `apps/ai-dpc/patients/std/A001/202610/cases_A001_2610.csv`（UTF-8 BOM）

D から取る列（1始まり）:

| 列 | 出力 |
|----|------|
| 2 | patient_id |
| 4 | admission_date |
| 3 | discharge_date |
| 29 | dpc_code |

日付は `YYYYMMDD` のまま。4列が完全一致する重複だけ落とす。退院日 `00000000`（在院）は残す。6–7月の手順では落としていたが、7日以内再入院を外せなくなるため誤り。9月以降は残している。

様式1は、データ識別番号が patient_id と一致し、コードが `A000010` の行から生年月日を取る。複数あれば先頭。`birthday` は `YYYY-MM-DD`、`age` は入院日時点の満年齢。取れなければ空欄。

列順:

```text
patient_id,admission_date,discharge_date,age,dept_code,primary_dept,readmit_flag,dpc_excluded,dpc_code,birthday
```

`dept_code` / `primary_dept` / `readmit_flag` / `dpc_excluded` は空欄。

報告するのは出力行数と、生年月日・年齢が空だった行数だけ。

### 7. コーディングを実行する

10月の作業ログには実行コマンドが無い。現行の `apps/ai-dpc/justfile` では次のとおり。熊本の係数対策は閾値 `0.7` を明示していた。滋賀のログに閾値は無い。キャッチアップは just の既定 `0.8` でよい。柳内さんの10月結果と数値を揃えるときだけ、使った閾値を確認する。

```bash
cd ~/ws/ai-dpc-multi-agent
V2_PATIENT_DATA_ROOT=apps/ai-dpc/patients/A001 \
  just dpc::run-openai A001 \
  apps/ai-dpc/patients/std/A001/202610/cases_A001_2610.csv \
  monthly 202610
```

先に数件だけ通す。問題がなければ全件。マスタの schema version は滋賀ログに記載が無い。熊本であった退院日による v1.1 / v1.3 の分割は、滋賀の月次ログには出てこない。

9月は main の hotfix が取り込まれておらず、一部症例だけ再実行している。今回は実行前に main を取ってから回す。

結果の要約に患者ID・氏名・診断名は出さない。件数と成否、出力ファイルの timestamp、失敗ステップだけ残す。
