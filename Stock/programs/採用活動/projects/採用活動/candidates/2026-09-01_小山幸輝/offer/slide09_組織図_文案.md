# Part 1：As-Is（現状）

## 組織イメージ

```
Product部門（部門Mgr：山田）

├ FDE（探索）
│     顧客課題を深掘りし、プロダクト化まで届ける
│     └ 黒川 … 深掘り〜実装（DataOps兼務）
│        山田 … 立ち上げ支援・案件PM（兼務）
│
├ Dev（継続）
│     foro等の価値を維持・改善する
│     └ 廣・新保 … 開発
│        山田 … EM（兼務）
│
├ DataOps（定例）
│     病院データを安定して届ける
│     └ 藤原 … 定例運用の中心
│        田尻・瀬谷・久保・高士 … 投入・品質
│        黒川・山田 … リード・連携（兼務）
│
└ 横断
      PdM・デザイン・Sec / AI / Infra の土台
      └ 山田 … PdM
         田中 … デザイン
         既存メンバー … AI / Infra / Sec（マトリクス）
```

## 各チームの役割（1行ずつ・表でも可）

| チーム | 役割 |
|--------|------|
| **FDE** | 現場の課題を捉え、設計・実装・検証まで届ける（探索） |
| **Dev** | 既存SaaS（foro等）の機能改善・安定運用（継続） |
| **DataOps** | 定例データ投入の安定稼働・品質管理（定例） |
| **横断** | PdM、デザイン、Sec/AI/Infraなど部門共通の土台 |

# Part 2：To-Be（1年後のイメージ — 想定パターン）

> スライドは **パターンA〜C** をカード3枚、または1枚に3列で配置。

---

## パターンA：FDEリードに専念（チーム立ち上げ型）

**こんなとき**: FDEチームの型づくり・案件完遂を最優先したい

```
FDE … 小山（リード）＋黒川＋メンバー
      ・2テーマ並行、CS/PSと一体で回す
      ・小山＝チームPM・顧客接続・優先度判断
      ・実装の中核は黒川＋メンバー

横断 … Sec推進は小山（基準・レビュー中心）
```

**小山さんの主戦場**: FDEチームの運営と、探索案件の完遂

---

## パターンB：FDEリード ＋ 横断（Sec・ガバナンス厚め）

**こんなとき**: 事業拡大に伴い、セキュリティ・技術ガバナンスを厚くしたい

```
FDE … 小山（リード）＋黒川＋メンバー
      ・案件は1〜2本に絞り、深く完遂
      ・チーム運営・CS/PS接続は小山

横断 … 小山がSec推進の中心
      ・基準策定・レビュー・部門横断のルールづくり
      ・Infra / 技術選定にも関与（TL補完寄り）
```

**小山さんの主戦場**: FDEのリード ＋ 部門横断の土台づくり（Sec中心）

---

## パターンC：FDEリード ＋ CS/PSデリバリー継続（現場×新規事業型）

**こんなとき**: 顧客理解を武器に、新サービス立ち上げまで踏み込みたい（スライド#8 Phase2寄り）

```
FDE … 小山（リード）＋黒川＋メンバー
      ・担当病院でのCS/PS伴走を継続
      ・医療事務AI等の新領域を、事業責任者の右腕として推進

Dev / DataOps … 既存チームが自律運営
      ・廣リードのDev、黒川リードのDataOps
```

**小山さんの主戦場**: 現場の顧客理解 × 新規事業・新サービスの立ち上げ

---

## パターンD（参考）：領域拡大・右腕型（〜3年の方向性）

**こんなとき**: 成果と本人の志向に応じて、Product部門全体の右腕へ（スライド#8 Phase3のイメージ）

```
小山 … FDEを超えて、探索領域またはProduct部門横断のオーナーシップ
      ・チーム複数の牽引、投資配分・優先度への関与
      ※入社直後の前提ではなく、中長期の可能性として
```
