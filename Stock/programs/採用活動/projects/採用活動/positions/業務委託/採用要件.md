> **スキルの土台**: [テックリード｜メダップ株式会社｜採用サイト](https://medup.notion.site/3731da5a7f3b81b18c52eb882ce5cf53)

> **作成**: 2026-10-05

見極めのスキル水準はテックリード募集要項に揃える。任せる仕事は、既存SaaSの保守・障害対応と、新保さんとの改修。

採否は [業務委託面談](https://app.notion.com/p/3f01da5a7f3b80249834f8f99218d825) の1回で決める。目的は、業務を説明したうえで、その期待に応えるスキルと人間性があるかを測ること。

見極めの一点は、細かく指示する人がいない状況で自律して動けること。問題を自分で検知し、指示を待たずに動く。自分で課題を見つけて、より良い形にするために改善していく。判断が難しいときだけ、調べた結果を持ってエスカレーションする。インフラでの例は、セキュリティアラートをきっかけに影響調査から対応まで自分で回す動きだが、質問ではアラートに限定しない。

## 条件

| 項目 | 内容 |
|------|------|
| 雇用形態 | 業務委託 |
| 入社 | **2026年11月（なるはや）** |
| 主戦場 | 既存SaaSの保守、障害対応 |
| 改修 | **新保さんとコンビ**で実施（コードレビュー、テストなど） |
| 技術の重心 | **インフラ（主にGCP）** |

## このポジションでやること

- 既存SaaSの保守
- 障害対応
- 新保さんと組んだ改修（コードレビュー、テストなど）

インフラは GCP（Cloud Run, AlloyDB, Cloud SQL, Cloud Build など）を主戦場にする。

## スキルセット（テックリードベース）

出典は [テックリード採用ページ](https://medup.notion.site/3731da5a7f3b81b18c52eb882ce5cf53) の「求めるスキルや経験」。このポジションでは、その水準に **GCPを中心としたインフラの強さ** を足して見る。

### 必須（Must）

- 共通基盤・共通ルールを、設計して「運用として定着」させた経験
- 既存プロダクトの技術品質（設計・負債・運用）を、チームが回る形で引き上げた経験
- プロダクト開発・運用フェーズで、セキュリティ担保をリードした経験
  - 基準の定義（何を守るか）と、開発プロセスへの組み込み
  - 運用としての回し方（受付、優先度、対応、再発防止）
  - 分担・連携の設計（開発/インフラ/マネジメント）
- 不確実性のある状況でも、論点を構造化し、トレードオフを言語化して意思決定を前に進められる
- **インフラ、主にGCPに強い**（保守・障害対応を自分で回せる）
- **2026年11月に着手できる**（なるはや）

### 歓迎（Nice to have）

- AIコーディング/LLM活用を前提にしたプロセス設計の経験
- 少人数制約下での標準化・自動化の推進
- レガシーの段階的改善
- 可観測性（ログ/メトリクス）や運用改善の推進
- 監査・顧客要求・ISMS等の対応経験
- SaaS/医療系など、規制・信頼性要求が高い領域での経験

### 主な使用技術（テックリード募集要項より）

- **インフラ**: GCP（Cloud Run, AlloyDB, Cloud SQL, Cloud Build など）、Docker、Sentry
- **バックエンド**: TypeScript, Node.js, Fastify, tRPC, Prisma, Kysely。データ基盤は Python。一部に旧 Rails
- **フロントエンド**: TypeScript, React, Next.js
- **データベース**: PostgreSQL, BigQuery
- **その他**: Azure (AADB2C), Cursor 等のAIコーディングツール

## スタンス（テックリード募集要項のカルチャーフィット）

- 施策を「仕組み」に落として、継続的に回せる
- トレードオフ（速度×品質/セキュリティ）を言語化し、合意形成できる
- 個人の頑張りではなく、チームの運用に落とし込める
- 顧客価値から逆算して、必要な基盤/ルール/優先度を組み立てられる
- 役割や枠にとらわれず、事業や組織の課題を「自分ごと」として捉える
