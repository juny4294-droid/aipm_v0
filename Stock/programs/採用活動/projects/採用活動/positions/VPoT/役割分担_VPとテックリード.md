# VPoT（CTO候補）× テックリード — 役割分担

> 採用サイト・選考クライテリア用の整理メモ（2026-09-02）  
> **採用方針の詳細**: [ポジション定義_採用方針.md](ポジション定義_採用方針.md)

## 一言で

| | テックリード | VPoT（CTO候補） |
|--|-------------|-----------------|
| **スコープ** | **担当プロダクト**の技術責任者 | **全社・プロダクト横断**の技術方針 |
| **問い** | このプロダクトをどう技術的に良くするか | プロダクト横断で技術的に最適な方針は何か |
| **視座** | プロダクト内のアーキ・品質・セキュリティ | マルチプロダクト横断のアーキ・インフラ・技術戦略 |
| **マネジメント** | 不要 | **今回も不要**（将来CTOとしては段階的に） |

**VPoTはテックリードの上位**。テックリードが担うプロダクト技術責任の領域を**理解し、自分でもできる**ことが前提。そのうえで、**プロダクト横断の全体最適**と**全社の技術方針**を握る。

---

## スコープの違い（核心）

```
全社・プロダクト横断の技術方針  ← VPoT（CTO候補）
  ├── マルチプロダクトで技術的に最適な方針は何か
  ├── プロダクト間の技術選定・共通化・負債の優先度
  ├── インフラ・クラウドアーキの全体設計
  └── 事業・プロダクト戦略との技術面での整合

担当プロダクトの技術責任者  ← テックリード
  ├── そのプロダクトのアーキテクチャ・技術選定
  ├── 品質・セキュリティ・技術負債の管理
  ├── AI駆動開発の進め方・レビューの型
  └── プロダクトチーム内の技術的意思決定
```

| 観点 | テックリード | VPoT（CTO候補） |
|------|-------------|-----------------|
| 単位 | **プロダクト**（担当分） | **全社・プロダクト横断** |
| アーキ | 担当プロダクトの設計・品質 | 複数プロダクトを**まとめた上での**最適な方針 |
| 技術選定 | プロダクト内の判断 | プロダクト横断の標準・例外の設計 |
| 技術負債 | 担当プロダクトの返済計画 | プロダクト横断の投資優先度づけ |
| インフラ | 担当プロダクトの運用・セキュリティ | 全社のインフラ・クラウドアーキ方針 |
| 会話相手 | プロダクトチーム・PdM | CEO・事業責任者・各TL・PdM |

---

## テックリードが担うこと

- **担当プロダクト**のアーキテクチャ・技術選定・技術負債
- プロダクトの技術品質（設計レビュー、運用判断軸）
- セキュリティ基準と運用フロー（担当プロダクト範囲）
- AI駆動開発の進め方・レビューの型（担当プロダクトへの定着）
- 速度×品質×セキュリティのトレードオフの言語化

→ **「このプロダクトを技術的に良い状態で回す」**責任者。

---

## VPoTに加わるレイヤー

テックリードの仕事ができるうえで、**スコープが一段上がる**。

### 1. 複数プロダクト横断の技術方針

- foro CRM、新規プロダクト、AI事業など**複数プロダクト**で技術的に最適な方針を考える
- プロダクト間の共通化・分離の判断、技術選定の標準と例外
- 統合データ基盤・インフラを含めた全体アーキ

### 2. 全社の技術戦略

- SaaS × データ基盤 × AI を一体で見た技術ロードマップ
- 技術的負債・投資判断の**プロダクト横断**での優先度づけ
- 開発・デプロイ・運用の共通基盤の方針

### 3. 事業・プロダクト戦略との整合

- CEO・事業責任者と、**技術の打ち手で事業をどう伸ばすか**を議論
- 各テックリードの判断を踏まえつつ、**全体最適**の視点で方針を決める

### 4. 技術ガバナンス

- 品質・セキュリティ・コンプライアンスの**全社方針**
- 各TLの判断軸をそろえる（個別プロダクトの実務はTLが担う）

---

## 重なりと分担のイメージ

```
事業戦略・プロダクト戦略
        ↕ 技術面での整合
全社・プロダクト横断の技術方針  ← VPoT（CTO候補）
        ↓ 方針・優先度・標準を渡す
担当プロダクトの技術責任  ← テックリード（プロダクトA / B / …）
        ↓
各チームのプロダクト開発（FDE / Dev / DataOps）
```

- **VPoT**：プロダクト横断で「技術的に何が最適か」を考え、方針を決める
- **TL**：担当プロダクトで「その方針をどう実現するか」を技術的にリードする
- **人のマネジメント**はどちらも主戦場ではない

---

## 採用サイトでの訴求ポイント

### テックリード

- 担当プロダクトの技術責任者として、品質・セキュリティ・アーキを握れる
- AI駆動開発の進め方をプロダクトに定着させられる

### VPoT（CTO候補）

1. **テックリードができる**（プロダクト技術の深さがある）
2. **その上で、全社・プロダクト横断**の技術方針を描ける
3. **マネジメント職ではなく技術責任者**──全体最適の設計・アーキに近い裁量
4. **CTO候補**として、プロダクト横断の技術をゼロから設計できる

## 選考での見極め（VPoT vs TL）

| 観点 | TL向き | VPoT向き |
|------|--------|--------|
| 関心の中心 | 担当プロダクトの技術品質・アーキ | プロダクト横断の技術方針・全体最適 |
| 実績の型 | プロダクトの技術基盤を設計・改善した | 複数プロダクト横断のアーキ方針を設計した |
| 思考の単位 | 「このプロダクトをどうするか」 | 「プロダクト横断で何が最適か」 |
| 会話の相手 | プロダクトチーム・PdM | CEO・事業責任者・各TL |
