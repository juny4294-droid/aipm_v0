# VPoT（CTO候補）— ポジション定義（採用方針）

> **2026-09-02 更新**  
> HERP募集要項（`募集要項_エンジニアVP候補.md`）は原文として保持（HERP上の職種名は「エンジニアVP候補」）。  
> **採用サイト・対外コミュニケーションでは「VPoT（CTO候補）」を使用。**  
> **Notionへの反映は指示があるまで行わない。**

---

## このポジションの本質

**全社・プロダクト横断の技術責任者**を採用する。

- 過去のVPoT募集は **データ基盤・データマネジメントの責任者** の色が強かった（データ戦略、BI/DWH、データOps）
- 今回は **プロダクト横断の技術方針・アーキテクチャ・インフラ** を握るポジション
- データ基盤も技術領域の一部として扱うが、**中心はプロダクト開発全体の技術設計とガバナンス**
- 組織や人のマネジメント（ライン管理・ピープルマネジメント）は**今回の採用要件としては求めない**
- ただし **CTO候補** として採用する以上、将来的には会社全体のマネジメントからは逃れなくなる──それは**到達目標**として位置づける

### 一言

> **テックリードの上位。担当プロダクトの技術責任はできるうえで、全社・プロダクト横断の技術方針を握る（CTO候補）。**

## テックリードとの関係

| | テックリード | VPoT（CTO候補） |
|--|-------------|-------------|
| **スコープ** | **担当プロダクト**の技術責任者 | **全社・プロダクト横断**の技術方針 |
| **問い** | このプロダクトをどう技術的に良くするか | プロダクト横断で技術的に最適な方針は何か |

VPはTLの仕事ができることが前提。そのうえで、プロダクトを個別に見るのではなく、**まとめた上での技術的な最適解**を考えるレイヤー。

詳細: [役割分担_VPとテックリード.md](役割分担_VPとテックリード.md)

## 過去版VPoTとの違い（重要）

| | 過去版 VPoT（データVP） | 今回 VPoT（CTO候補） |
|--|------------|-----------------|
| **責任の中心** | データ基盤・データマネジメント | **プロダクト全体の技術・アーキ・インフラ** |
| **主な業務像** | データ戦略、BI/DWH、データ利活用、データOps | 技術戦略、アーキ方針、マルチプロダクト設計、インフラ、技術ガバナンス |
| **データの位置づけ** | **主戦場** | 技術領域の**一部**（統合データ基盤はアーキの構成要素） |
| **プロダクト開発** | 間接的（データを通じた価値創出） | **直接**（SaaSプロダクト群の技術方針・品質・運用体制） |
| **インフラ** | データ基盤（BigQuery等）中心 | **プロダクト＋全社**のインフラ・クラウドアーキ |
| **組織像** | データ組織のVP | 技術責任者（マネジメント職ではない） |
| **年収** | 810万円〜 | 1,000万〜1,500万円 |

### 技術領域の全体像（今回の責任範囲）

```
VPoT（CTO候補）
├── プロダクト技術
│   ├── マルチプロダクト（foro CRM 等）の技術方針・保守運用体制
│   ├── アプリケーションアーキテクチャ
│   └── AI事業の技術設計・導入方針
├── アーキテクチャ
│   ├── マルチプロダクト横断の設計方針
│   ├── 技術選定・技術負債の投資判断
│   └── 統合データ基盤（データはここに含まれるが、それだけではない）
├── インフラ
│   ├── クラウドアーキテクチャ（GCP等）
│   ├── 運用・可観測性・セキュリティ基盤
│   └── 開発・デプロイの共通基盤
└── 技術ガバナンス
    ├── 品質・セキュリティ・コンプライアンスの方針
    └── 事業・プロダクト戦略との技術面での整合
```

**DataOpsチーム**（データ運用の日次業務）は別枠。VPはデータ基盤の**設計方針**を握るが、データマネジメントの実務責任者ではない。

## 求めること / 求めないこと

### ✅ 求める（主戦場）

| 領域 | 内容 |
|------|------|
| **プロダクト技術** | 複数SaaSプロダクト横断の技術方針、保守・運用体制、AI事業の技術設計 |
| **技術戦略** | SaaS × データ基盤 × AI を一体で見たロードマップ（**データだけに閉じない**） |
| **アーキテクチャ** | マルチプロダクト設計、技術選定、技術負債の投資判断、統合データ基盤の全体設計 |
| **インフラ** | クラウドアーキ（GCP等）、運用基盤、開発・デプロイの共通基盤 |
| **事業との整合** | 事業戦略・プロダクト戦略と技術戦略のすり合わせ、経営層との技術対話 |
| **技術ガバナンス** | 品質・セキュリティ・コンプライアンスの方針と投資判断 |
| **テックリード領域の上位** | 横断基盤・品質・セキュリティを理解し、方針・優先度を握れる |
| **技術組織の設計** | 開発体制・役割分担・技術的意思決定の仕組み（≠ 人事マネジメント） |

### ❌ 今回は主要件にしない

| 領域 | 補足 |
|------|------|
| **データマネジメントの実務責任** | データOpsの日次運用はDataOpsチームが担う。VPはデータ基盤の**設計方針**を握る |
| **ピープルマネジメント** | 評価・1on1・メンバー育成の日常運用はProduct部門MG等が担う想定 |
| **ライン管理** | 直属部下の人事管理・評価制度運用 |
| **採用の主担当** | 採用計画の策定・実行のオーナーではない（技術面の要件定義・面接判断への関与は可） |
| **文化づくりの主担当** | 開発文化は技術方針の定着として語るが、HR的な組織文化構築は対象外 |

### 🔮 将来（CTO到達時）

- 会社全体の技術・開発に関する意思決定
- 経営会議での技術リード
- 組織拡大に伴うマネジメント（段階的に）

→ **「今は技術責任者として採用し、CTOとして育つ」** というストーリー。

## テックリードとの関係（再整理）

```
事業戦略・プロダクト戦略
        ↕ 技術面での整合
全社・プロダクト横断の技術方針  ← VPoT（CTO候補）
        ↓ 方針・優先度・標準
担当プロダクトの技術責任  ← テックリード
        ↓
各チームのプロダクト開発
```

| | テックリード | VPoT（CTO候補） |
|--|-------------|-------------|
| 主語 | 「このプロダクトをどうするか」 | 「プロダクト横断で何が最適か」 |
| 視座 | プロダクト内のアーキ・品質・セキュリティ | マルチプロダクト横断のアーキ・インフラ・技術戦略 |
| マネジメント | 不要 | **今回も不要**（技術的リードは必要） |
| 会話相手 | プロダクトチーム・PdM | CEO・事業責任者・各TL |

## HERP原文との差分（採用文面で調整する箇所）

HERP原文には以下が含まれるが、**採用メッセージでは弱める／言い換える**：

| HERP原文 | 採用方針での言い換え |
|---------|-------------------|
| 開発組織のマネジメントをリード | **技術面から開発組織を設計・牽引** |
| ピープルマネジメント | **技術リード・技術的意思決定のリード** |
| 採用計画の策定・実行 | **採用への技術的関与**（要件定義・技術面接） |
| 開発チームのマネジメント経験（必須） | **技術リード経験**（チーム牽引・設計判断・アーキ推進） |
| エンジニア採用業務（必須） | **歓迎**に格下げ、または「技術面での採用関与」 |

## 採用サイトでの訴求軸

1. **医療×SaaS×AIの事業拡張**に合わせ、プロダクト横断の技術戦略をゼロから描ける
2. **データVPではなく、全社・プロダクト横断の技術責任者**──アーキ・インフラ・ガバナンス
3. **テックリード領域の深さ**があり、技術的に信頼できる責任者
4. **マネジメント職ではなく技術責任者**──設計・アーキに近い裁量で事業と技術をつなぐ
5. **CTO候補**として、経営層と技術戦略を語れる

## 選考での見極め

| プラス | マイナス |
|--------|---------|
| 複数プロダクト横断のアーキ・技術方針を設計した | データ分析・BI/DWH中心のキャリアのみ |
| プロダクト開発＋インフラの両面を見渡せる | データマネジメント・DataOps実務が主戦場 |
| 技術戦略を経営と合意した経験 | マネジメント職志望で技術から離れたい |
| テックリード領域を自分で推進した実績 | 単一プロダクト内の実装リード止まり |
| 事業課題から技術投資を逆算できる | 技術より組織運営・採用が中心の実績のみ |
