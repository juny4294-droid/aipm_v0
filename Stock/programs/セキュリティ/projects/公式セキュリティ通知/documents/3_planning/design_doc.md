## 1. コンテキストとスコープ

### 問題の説明

npm のライブラリは Dependabot が見ている。自分たちで載せて、自分たちでパッチする言語・ミドルウェア・OS の公式セキュリティ告知は、別の仕組みがないと気づくのが遅れる。

このシステムは、バージョン一覧に載っている対象のうち「監視」が「あり」の行について、公式の告知を読み、そのバージョンに当たったものだけを Slack に出す。

### 背景

バージョンの台帳は Notion の「バージョン一覧」である。

https://app.notion.com/p/4131da5a7f3b807c8ad7d57c75bd8d9f

ページ ID は `4131da5a-7f3b-807c-8ad7-d57c75bd8d9f`。列は「対象」「リポジトリ」「バージョン」「サポート期限」「監視」。監視の値は「あり」または「なし」。更新の基準は [バージョン一覧の更新手順](バージョン一覧の更新手順.md)。

2026-11-16 時点で動いているのは上段（言語、アプリサーバ、DB、Redash 上の一部ミドルウェア）だけである。実行場所は Google Apps Script。プロジェクト名は `security-advisory-notifier`。1時間おきに関数 `post` を実行する。投稿先は山田潤の DM（ユーザー ID `U0AJ8PR3AN8`）。

作業記録は `documents/4_executing/20261116_手順1_slackアプリ.md` と `documents/4_executing/20261116_手順2_定期実行.md`。コードは `development/code/Code.gs`。

## 2. 目標と非目標

### 目標

- 公式の告知のうち、監視対象のバージョンに当たったものだけを Slack に届ける。
- 新しい告知がなければ、DM を増やさない。
- 告知の取得に失敗した回は、失敗であることを DM で分かるようにする。
- バージョン一覧の「監視」が「あり」の行が変わったら、次の実行で監視側のバージョンを更新する。
- バージョン一覧が読めない回も、前回保存したバージョンで告知の確認を続ける。

### 非目標

- npm ライブラリの監視。Dependabot に任せる。
- OS の監視。Debian、Ubuntu、Alpine、Linux カーネルはバージョン一覧で「なし」。
- Redash 本体の監視。公式のセキュリティ告知がないため「なし」。
- バージョン一覧に無いバージョンを、リポジトリから自動で拾うこと。
- Gmail、Blogtrottr、Feedrabbit、キーワード転送。
- 新しい GCP プロジェクトやサーバー。

## 3. 設計概要

毎時、`post` が次の順で動く。

1. Notion のバージョン一覧を読む。
2. 「監視」が「あり」の行から、今回使うバージョン一覧を作る。
3. 前回保存した `watch_list` と違えば、`watch_list` を上書きする。同じならそのまま。読めなければ `watch_list` を変えず、その内容で続ける。
4. 製品ごとの公式の告知を取り、バージョンに当たったものだけを残す。
5. 既読でないものだけを Slack に出す。出した ID は、投稿に成功したあと既読にする。

新しい告知がなく、一覧も読めて、未知の製品もなければ、Slack には何も出さない。

## 4. 詳細設計

### 技術的アプローチ

実行基盤は Google Apps Script。画面上の関数一覧は、手動で **実行** を押したときにだけ効く。1時間おきのトリガーは `post` を呼ぶ。

手動の関数は次の3つ。

| 関数 | 動き |
| --- | --- |
| `preview` | 件数をログに出す。Slack には出さない |
| `seed` | 今見えている告知を既読にする。取得に失敗した製品があると既読にしない。Slack には出さない |
| `post` | 既読でない告知だけを Slack に出す |

製品ごとの取り方はコードの `FEEDS` に固定する。バージョンの数字はコードに置かない。

| 対象 | 取得先 | バージョンの見方 |
| --- | --- | --- |
| Node.js | `https://nodejs.org/en/feed/vulnerability.xml` | メジャーだけ。`22.23.4` は `22` |
| Ruby | `https://www.ruby-lang.org/en/feeds/news.rss` | メジャーとマイナー。配信文に security または CVE があるものだけ |
| Ruby on Rails | `https://discuss.rubyonrails.org/c/security-announcements/9.rss` | メジャーとマイナー |
| Python | `https://mail.python.org/archives/list/security-announce@python.org/feed/` | メジャーとマイナー |
| PostgreSQL | `https://www.postgresql.org/news.rss` | 10 以上はメジャーだけ。`18.1` は `18`。9 以前はメジャーとマイナー。`9.6.24` は `9.6`。タイトルが PostgreSQL で始まり、配信文に security または CVE があるものだけ |
| Next.js | GitHub `vercel/next.js` の security advisories。パッケージ名 `next` | 一覧のバージョンと完全一致 |
| Redis | GitHub `redis/redis`。パッケージ名 `redis` | 完全一致 |
| Bun | GitHub `oven-sh/bun`。パッケージ名 `bun` | 完全一致 |
| nginx | `https://nginx.org/en/security_advisories.html` | 完全一致 |

RSS で本文が空のときは、記事ページを最大20件まで取りにいく。セキュリティかどうかは配信文だけで決め、ページ全体のメニュー語では決めない。

GitHub の範囲は、記号が1つだけのものを見る。`>= 16.0.0` や `<= 15.5.28` は見る。カンマや空白で条件が2つある範囲は、今の実装では見ない。

同じ製品・同じ系列・同じバージョン・同じサポート期限の行は、リポジトリを1つにまとめる。

サポート期限が今日（Asia/Tokyo）より前の行は、メッセージに「修正版は出ない」を付ける。期限が「なし」の行には付けない。

Slack の1件は次の形。

```text
{製品}  {タイトル}
該当: {リポジトリ}（{バージョン}）。修正版は出ない
{URL}
```

「修正版は出ない」は、サポート期限が過ぎている行だけに付く。複数行は `; ` でつなぐ。

一覧に、取り方を知らない製品が「あり」で入っているときは、その製品を除いて確認を続ける。DM は「取り方が未定義です: {製品名}。それ以外は確認しました。」。直すか「なし」に戻すまで、1時間ごとに届く。

「監視」が「あり」の行が1つもない、または「監視」列が見つからないときは、一覧を読めなかったものとして扱う。

### データモデル/ストレージ

保存先は GAS のスクリプトプロパティ。コードや Git には秘密情報を書かない。

| プロパティ | 内容 |
| --- | --- |
| `watch_list` | いま使うバージョン。JSON。一覧が読めて前回と違うときだけ上書きする |
| `seen_ids_0` 以降 | 既読の告知 ID。1件あたり約8KBで分割する |
| `SLACK_BOT_TOKEN` | Slack の Bot Token。スコープは `chat:write` のみ |
| `SLACK_CHANNEL` | `U0AJ8PR3AN8` |
| `GITHUB_TOKEN` | 公開情報だけを読む classic token。スコープのチェックは付けていない |
| `NOTION_TOKEN` | 個人アクセストークン。期限は 2027-11-16 |

`Code.gs` の `WATCHES` は、`watch_list` がまだ無いときの初期値。2026-11-16 の `preview` で Notion の内容を `watch_list` に保存済みなので、以降の実行は `watch_list` を使う。

ローカルの `development/code/notify.py` と `watches.yaml` は、GAS に移す前の同じ判定を確認した実装。定期実行は GAS だけが行う。`.env`、`state.json`、`.venv` は Git に入れない。

### 告知の取得に失敗したとき

製品ごとの取得失敗は、その回の告知投稿と既読更新を止める。DM は次の形。

```text
セキュリティ告知の取得に失敗しました
{製品}: {詳細}
この回は新しい告知を確認できていません。
```

失敗が続いているあいだは、1時間ごとに同じ DM が届く。

バージョン一覧が読めないときは、告知の確認は止めない。`watch_list` で探し、次の DM を1通出す。

```text
バージョン一覧を読めなかったので、前回のバージョンで確認しました。
```

新しい告知がなければ、この1通だけである。

### バージョンを変えたとき

Node.js を `22.23.4` から `22.24.0` にしても、見ている系列は `22` のまま。当たる告知は変わらず、DM に出るバージョン表示だけが変わる。

Next.js、Redis、Bun、nginx は完全一致なので、バージョンを変えると当たる告知の範囲が変わる。新しいバージョンにだけ当たる、すでに公開済みの告知が届くことがある。系列を新しく足したときも同じ。

リポジトリ側のバージョンが上がっても、バージョン一覧を直すまでは `watch_list` は変わらない。

## 5. 代替案と検討したトレードオフ

### 検討した代替案

- Cloud Run と Cloud Scheduler。新しい GCP プロジェクトを作る案。サーバーを増やさないため止めた。
- Gmail のフィルタと、Blogtrottr などの転送。バージョン範囲の判定ができず、第三者が告知を見るため止めた。
- 毎時 Notion を読み、読めない回は監視ごと止める案。バージョン変更は頻繁ではないため、前回の `watch_list` で続けることにした。
- 内部コネクト。このワークスペースでは作成権限がなかった。個人アクセストークンにした。

### 選定の理由

GAS の時間トリガーなら、追加のサーバーなしで1時間おきに動く。バージョンの正は、人が更新するバージョン一覧にする。読めない回も前回の一覧で告知を探せる。

## 6. 懸念事項と考慮点

### セキュリティの考慮点

- Slack、GitHub、Notion のトークンはスクリプトプロパティだけに置く。チャット、Notion、Git、この設計文書には書かない。
- Slack アプリのスコープは `chat:write` のみ。イベント購読はない。
- GitHub トークンにスコープは付けていない。公開情報だけを読む。
- Notion の個人アクセストークンは、発行した人が見られるページを、その人と同じ範囲で操作できる。バージョン一覧の1ページだけには絞れない。期限は 2027-11-16。
- GitHub トークンの期限が切れると、Next.js、Redis、Bun の取得が失敗する。その回は告知を出さず、既読も更新しない。失敗 DM が1時間ごとに届く。GitHub からは、トークンを作ったアカウントのメールに更新案内が来る。GAS の失敗メールは来ない。取得失敗はスクリプトの中で受け止め、実行自体は成功になるため。
- Notion トークンの期限が切れても、告知の確認は `watch_list` で続く。一覧を読めなかった DM が1時間ごとに届く。

### その他の懸念事項

- 画面上の関数が `preview` でも、1時間おきのトリガーは `post` のまま動く。
- 既読は告知 ID ごと。バージョンを上げても、同じ告知 ID は再通知しない。そのバージョンにだけ当たる別の告知は届く。
- 2026-11-16 に既読へ入れたのは 76 件。内訳は Node.js 20、Ruby 3、Ruby on Rails 12、Python 3、PostgreSQL 1、Next.js 6、Redis 1、Bun 1、nginx 29。
- Ruby の通常リリースでも本文に security があると該当することがある。
- Python の `3.14` は `3.14.0` として比較する。`3.14.10` だけが対象の告知も、範囲に入れば当たる。
- nginx 1.9.10 は広い脆弱性範囲に入る。既読済みのため、同じ CVE は再通知しない。

## 7. 実装とテスト計画

### 実装計画

2026-11-16 に上段の監視まで完了した。OS の高重要度通知は、上段が落ち着いてから別途検討する。

### テスト方針

2026-11-16 に確認したこと。

- `preview` の合計は 76 件。Slack には出ていない。
- `seed` の既読は 76 件。GitHub トークンを入れる前の 68 件は、この実行で上書きした。
- その直後の `post` は「新しい告知はありません」。DM は増えていない。
- バージョン一覧を読む `preview` は「バージョン一覧の更新を保存しました」のあと、合計 76 件。Slack には出ていない。

### モニタリングとメトリクス

健全性は DM の有無で見る。

- DM がない: 一覧を読めて、新しい該当告知がない。
- 「取得に失敗しました」: 告知の取得に失敗し、その回は確認できていない。
- 「バージョン一覧を読めなかったので、前回のバージョンで確認しました」: 告知の確認は前回の `watch_list` で行った。
- 製品名と URL のある DM: 新しい該当告知。
