# 脳神経外科の月次抽出手順（鳥取県立中央病院）

更新: 2026-11-09。最初の手順は、対象月のデータが揃っているかの確認。

tenant 274。済生会などの `outpatient-ops` パイプラインとは別で、BigQuery に SQL を直接実行する。クエリは逆紹介候補を出すところまで。翌月の通院予約との突合は、このクエリでは行わない。整形・泌尿も、受領と投入の確認先はこの節と同じ。

## 実行前に確認すること

これが最初の手順。対象月の決め方は次の「期間」。確認は次の順。

1. 受領ファイルが Drive にある
2. foro core admin（MIS管理画面）で、そのファイルがテーブルに投入済みである
3. BigQuery で、対象月の日付まで入っている

来月の通院予約は、候補を出したあとに患者IDと突合する。候補抽出の入力ではない。外来の E行が対象月まで無ければ、期間をクエリに書いて実行しない。入院EFは見ない。

### 対象月まで入っているか

`bq query` が認証エラーなら、先に `gcloud auth login` する。

対象月が揃ってから実行する。確認クエリの `2026-08-01` / `2026-08-31` は、その回の対象月に読み替える。

```sql
SELECT
  MAX(IF(action_detail_number = 0, outpatient_date.value, NULL)) AS max_e_date,
  COUNTIF(action_detail_number = 0 AND outpatient_date.value BETWEEN DATE '2026-07-01' AND DATE '2026-07-31') AS prev_e_rows,
  COUNTIF(action_detail_number = 0 AND outpatient_date.value BETWEEN DATE '2026-08-01' AND DATE '2026-08-31') AS month_e_rows,
  COUNT(DISTINCT IF(action_detail_number = 0 AND outpatient_date.value BETWEEN DATE '2026-08-01' AND DATE '2026-08-31', outpatient_date.value, NULL)) AS month_e_days,
  COUNTIF(action_detail_number > 0 AND outpatient_date.value BETWEEN DATE '2026-08-01' AND DATE '2026-08-31') AS month_detail_rows,
  COUNTIF(action_detail_number > 0 AND receipt_code = '170020470' AND outpatient_date.value BETWEEN DATE '2026-08-01' AND DATE '2026-08-31') AS month_contrast_rows
FROM `medup-foro.dpc_patient_records_prd.outpatient_ef`
WHERE tenant_id = 274
  AND data_type != 'SY';
```

| 確認 | 揃ったと判断する目安 | 欠けると |
|------|----------------------|----------|
| `outpatient_ef` の E行（`action_detail_number = 0`） | 最大受診日が対象月末。対象月の行数は前月と同じ桁。受診日が月の日数ぶんある | 母集団・MRI・併科・CT・てんかんが欠ける。実行しない |
| 明細行（`action_detail_number > 0`）と造影加算 `170020470` | 対象月の明細行があり、造影加算が 0 ではない | NX5（最新MRIが造影か）が欠ける |
| `public_hospital_admissions` の `admission_ended_on` | 最大日が対象月末以降。対象月の退院がある | NX4（血管内の入院K）・NX7（SAH）が欠ける |
| `public_reverse_referrals` の `reverse_referral_date` | 最大日が対象月末以降 | NX8 がその月の逆紹介を見ない。ユーザー提出待ちのことがある |
| `dbt_int_doctor_department` | tenant 274 に診療科名 `脳神経外科` がある | 母集団が 0 になる |

入院と逆紹介の確認:

```sql
SELECT 'reverse_referrals' AS src, MAX(reverse_referral_date) AS max_date,
  COUNTIF(reverse_referral_date BETWEEN DATE '2026-08-01' AND DATE '2026-08-31') AS month_n
FROM `medup-foro.foro_prd.public_reverse_referrals`
WHERE tenant_id = 274
UNION ALL
SELECT 'admissions', MAX(admission_ended_on),
  COUNTIF(admission_ended_on BETWEEN DATE '2026-08-01' AND DATE '2026-08-31')
FROM `medup-foro.foro_prd.public_hospital_admissions`
WHERE tenant_id = 274;
```

逆紹介だけ遅れる場合は、欠ける月をメモに書いてから実行してよい。2026-09-30 は外来・入院が 8/31 まで、逆紹介は 7/31 までだったので、その状態で実行した。外来の E行が対象月まで無いときは、この例外にはしない。

2026-09-30 時点の目安: 8月の E行 156,675（31日、7月は 168,569）、明細行 347,055、造影加算 88、入院 1,095。

2026-10-27 時点: 外来EF・入院・逆紹介・紹介の最大日はいずれも 2026-09-30。9月の E行は 161,258（30日）。10月実行分は抽出済み。

2026-11-09 時点: 外来EF・入院・逆紹介の最大日はいずれも 2026-09-30。10月の E行は 0。9月の E行は 161,258。窓は繰っていない。

## 期間

直近12か月分の完結した月。実行月を M とすると、通常は M-1 月までが入っている。

- `period_end`: M-1 月の末日
- `period_start`: `period_end` から見て12か月前の、その翌月1日
- `sah_lookback_start`: `DATE_SUB(period_end, INTERVAL 5 YEAR)`（NX7）

例: 2026-09 に実行 → `2025-09-01` 〜 `2026-08-31`。2026-10 に実行 → `2025-10-01` 〜 `2026-09-30`。

リストAとファネルの `params` を両方変える。日付だけ変える。条件は変えない。

## クエリの扱い

条件の文章は [20260807_抽出条件確認用_3診療科](https://app.notion.com/p/3b51da5a7f3b8191b014e46afe9ba2a4) の「脳神経外科」。実行するときは Stock のクエリをコピーする。

- 次回以降の元ネタ: `documents/4_executing/queries/脳神経外科_N4追加後/`（2026-11-05。N4追加後）
- 修正前: `documents/4_executing/queries/脳神経外科_N4追加前/`（2026-10-27 に実行したクエリそのもの）

対象は N1 ∧ N2 ∧ (N3 ∨ (N4_1 ∧ N4_2))。

- N3: 期間内のMRI（`170020110` / `170033510`）。磁場では絞らない
- N4_1: 脳外の最大行為が `5.検査（US・XP含む）`
- N4_2: 脳外受診に `160165010` が1回以上
- 除外フラグは NX1、NX2、NX4〜NX8。行は除外で消さない。`最終候補 = 1` が全フラグ 0
- **NX3（神部先生の予約）は適用しないのが正**（2026-09-30、CS合意。[Slack](https://medup.slack.com/archives/C09E6V3SB98/p1788227695432349)）。実行される `nx3` は空集合のまま。予約JOINはコメントに残し、予約データが入っても有効にしない。神部先生は、あとで予約の担当医フィルタで外す。
- 患者IDは `CAST(SAFE_CAST(x AS INT64) AS STRING)`。
- このクエリは翌月の通院予約と突合しない。済生会などは抽出スクリプトの中で当月予約CSVと内部結合する。鳥取は候補を出したあと、別作業で突合する。

## 実行

作業フォルダは `Flow/YYYYMM/YYYY-MM-DD/外来適正化_鳥取県立中央データ抽出/`。

1. `queries/脳神経外科_N4追加後/` のリストAとファネルをコピーし、期間を今回の値にする。
2. ファネルを実行し、件数を前月メモと比べる。
3. リストAを実行する。行数はファネルの `n_target` と一致すること。`NX3_神部` は全行 0。`最終候補 = 1` の件数はファネルの最終候補と一致すること。
4. リストAを次のファイル名で置く。

`鳥取県立中央病院_脳神経外科_逆紹介対象患者リスト_YYYYMMDD.csv`

中身は除外フラグ付きの全行（対象者全員。除外しても行は残す）。

5. ツール投入用は `最終候補 = 1` の `患者ID` 列だけを別CSVにする。ヘッダー必須。
6. 抽出メモに期間、ファネル、前月比、逆紹介の未反映月を書く。

2026-11-09 の再実行（期間 2025-10-01〜2026-09-30、N4追加後。10月は未投入）: ファネルは 11/05 と同一。最終候補 185。出力は `Flow/202611/2026-11-09/外来適正化_鳥取県立中央データ抽出/`。リストAは 11/05 と行単位で一致。

2026-11-05 に N4 を追加。比較は 10/27 と同じ期間（2025-10-01〜2026-09-30）: 脳外外来 1,238 → N3 736 → N4 60 → 対象 782 → 最終候補 185（増分 6）。クエリは `queries/脳神経外科_N4追加後/`。

2026-10-27（期間 2025-10-01〜2026-09-30、逆紹介は 9/30 まで。N4なし）: 脳外外来 1,238 → MRIあり 736 → NX8 92 → 最終候補 179。出力は `Flow/202610/2026-10-27/外来適正化_鳥取県立中央データ抽出/`。クエリは `queries/脳神経外科_N4追加前/`。

2026-10-01 の再実行（期間 2025-09-01〜2026-08-31、逆紹介は 8/31 まで）: 脳外外来 1,233 → MRIあり 733 → NX8 93 → 最終候補 175。出力は `Flow/202610/2026-10-01/外来適正化_鳥取県立中央データ抽出/`。9/30 時点（逆紹介 7/31 まで）は最終候補 176、NX8 89。

## このクエリのあと

10月分なら、10月の通院予約と患者IDを突合し、その月に来る人だけを実際の逆紹介対象にする。神部先生は予約の担当医で除外する。リストの患者IDだけでは、ツールの一覧は空になることがある。
