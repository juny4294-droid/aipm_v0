# 月次抽出手順（新東京病院）

環境は構築済み。リポジトリは `~/ws/outpatient-ops`。初回のクローンや `uv sync` は不要。

更新: 2026-10-23。このファイルは新東京だけ。済生会と鳥取は別の手順。

tenant 135。心臓内科と糖尿病内科。抽出の前に、対象月のデータが揃っているかを確認する。

## 1. 必要なデータが揃っているか確認する

ここが最初の手順。確認は次の順。

1. 受領ファイルが Drive にある
2. foro core admin（MIS管理画面）で、外来EFがテーブルに投入済みである
3. BigQuery で、対象月の日付まで入っている

揃えるもの。

- 前月までの外来EF（Eg）
- 来月の心臓内科予約xlsx（シートは「心内予約」「手術」「内視鏡」）
- 来月の糖尿病内科予約xlsx（シートは「Sheet1」「手術」「内視鏡」）

実行月を M とすると、外来EFの対象月末は M-1 月の末日、予約ファイルは M+1 月分。2026-10 に実行するなら、外来EFは 2026-09-30 まで、予約は 202611。外来EFが対象月まで無ければ抽出しない。予約xlsxが無ければ、あとの「予約xlsxを置く」に進まない。外来EFが欠けているときは、予約があっても抽出しない。入院データは見ない。

郵便番号（`data/135/ID_郵便番号.xlsx`）と、心臓内科の外勤先リスト（`data/135/新東京病院_外勤先リスト.xlsx - 心臓内科.csv`）は月次の受領データではない。手元のファイルをそのまま使う。糖尿病内科の紹介先は yaml の `facility_label_id` / `facility_selection_id` で、ファイルは差し替えない。

### 受領ファイル

[新東京の受領フォルダ](https://drive.google.com/drive/u/0/folders/1PuAtQQQqT1ivaPKaqvAD4Dg9EnBB1ZiP)。外来EFと予約xlsxはここを見る。外来EFのファイル名は `Eg_122415750_` と `Fg_122415750_` で始まる。予約xlsxは、実行前にこのフォルダから `data/135/` へ置く。

### テーブル投入

[新東京の外来EF](https://admin-web.medup-core-service.com/foro-core/tenants/135?tab=outpatientEF)。Drive にファイルがあっても、対象月が未登録なら抽出しない。投入の有無は [データ受領/投入状況一覧](https://admin-web.medup-core-service.com/foro-core/data-importing-logs) でも見る。

### 対象月まで入っているか

`bq query` が認証エラーなら、先に `gcloud auth application-default login` する。確認クエリの `2026-08-01` / `2026-09-01` / `2026-09-30` は、その回の前月と対象月に読み替える。

```sql
SELECT
  MAX(IF(action_detail_number = 0, outpatient_date.value, NULL)) AS max_e_date,
  COUNTIF(action_detail_number = 0 AND outpatient_date.value BETWEEN DATE '2026-08-01' AND DATE '2026-08-31') AS prev_e_rows,
  COUNTIF(action_detail_number = 0 AND outpatient_date.value BETWEEN DATE '2026-09-01' AND DATE '2026-09-30') AS month_e_rows,
  COUNT(DISTINCT IF(action_detail_number = 0 AND outpatient_date.value BETWEEN DATE '2026-09-01' AND DATE '2026-09-30', outpatient_date.value, NULL)) AS month_e_days
FROM `medup-foro.dpc_patient_records_prd.outpatient_ef`
WHERE tenant_id = 135
  AND data_type != 'SY';
```

最大受診日が対象月末以降で、対象月の E行が前月と同じ桁、受診日が月の日数ぶんあることを確認する。無ければ CS 経由で要求する。

2026-10-21 時点: 最大受診日は 2026-08-31、9月の E行は 0（`Eg_122415750_2608.txt`）。10月実行分（対象月末 2026-09-30）はここで止めている。

## 2. 予約xlsxを置く

手順1で見た予約月のファイルを `data/135/` に置く。

- `新東京_YYYYMM予約データ_心臓内科.xlsx`
- `新東京_YYYYMM予約データ_糖尿病内科.xlsx`

ファイル名の月と中身を揃える。シート名は変えない。心臓内科の予約シートは「心内予約」、グループの絞り込みは `心臓内科ＨＣＬ`。糖尿病内科の予約シートは「Sheet1」、グループの絞り込みは `内科ＨＣＬ`。

## 3. yaml のパスと期間を更新する

糖尿病内科は、期間内に在宅自己注射指導管理料を算定した患者を除外するのがデフォルト（2026-09の要望。今後もこの方針）。実装は `diabetes_v2_1`。対象は指導管理料の本体6コードで、加算は含めない。心臓内科にはこの除外はない。

使うのは次の2つ。`cardiology.py`、`diabetes.py`、`diabetes_v2.py`（自己注射除外なし）は実行しない。

- `src/pipeline/tenants/t135/cardiology_v2.yaml`
- `src/pipeline/tenants/t135/diabetes_v2_1.yaml`

両方の `appointment_xlsx` を置いたファイルにする。`start_date` / `end_date` は、手順1で揃っていた対象月までの直近12か月にする。2026-09 に実行するなら `2025-09-01` から `2026-08-31`。2026-10 に実行するなら `2025-10-01` から `2026-09-30`。シート名、グループ、郵便番号、外勤先、施設IDは変えない。

## 4. 実行する

`~/ws/outpatient-ops` で、心臓内科から実行する。

```bash
uv run python -m src.pipeline.tenants.t135.cardiology_v2
uv run python -m src.pipeline.tenants.t135.diabetes_v2_1
```

BigQuery の認証が切れていたら、先に `gcloud auth application-default login` する。
