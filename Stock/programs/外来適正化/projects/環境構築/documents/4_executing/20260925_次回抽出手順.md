# 次回の抽出手順（済生会熊本）

環境は構築済み。リポジトリは `~/ws/outpatient-ops`。初回のクローンや `uv sync` は不要。

更新: 2026-10-23。このファイルは済生会熊本だけ。新東京と鳥取は別の手順。

抽出の前に、対象月のデータが揃っているかを確認する。

## 1. 必要なデータが揃っているか確認する

ここが最初の手順。tenant 11。確認は次の順。

1. 受領ファイルが Drive にある
2. foro core admin（MIS管理画面）で、外来EFがテーブルに投入済みである
3. BigQuery で、対象月の日付まで入っている

揃えるもの。

- 前月までの外来EF（Eg）
- 来月の外来予約CSV（泌尿器科・呼吸器外科）
- 来月の手術予約CSV（泌尿器科のみ）

実行月を M とすると、外来EFの対象月末は M-1 月の末日、予約ファイルは M+1 月分。2026-10 に実行するなら、外来EFは 2026-09-30 まで、予約は 202611。外来EFが対象月まで無ければ抽出しない。予約CSVが無ければ、あとの「予約CSVを置く」に進まない。外来EFが欠けているときは、予約があっても抽出しない。入院データは見ない。

### 受領ファイル

外来EFは [受領フォルダ](https://drive.google.com/drive/u/0/folders/1pyo8eIEPpCZl3bQIntUx7PmWeAM5-g-B)。ファイル名は `Eg_` で始まる。予約CSVは別入手で、`data/11/` に置く。

### テーブル投入

[済生会の外来EF](https://admin-web.medup-core-service.com/foro-core/tenants/11?tab=outpatientEF)。Drive にファイルがあっても、対象月が未登録なら抽出しない。投入の有無は [データ受領/投入状況一覧](https://admin-web.medup-core-service.com/foro-core/data-importing-logs) でも見る。

### 対象月まで入っているか

`bq query` が認証エラーなら、先に `gcloud auth application-default login` する。確認クエリの `2026-08-01` / `2026-09-01` / `2026-09-30` は、その回の前月と対象月に読み替える。

```sql
SELECT
  MAX(IF(action_detail_number = 0, outpatient_date.value, NULL)) AS max_e_date,
  COUNTIF(action_detail_number = 0 AND outpatient_date.value BETWEEN DATE '2026-08-01' AND DATE '2026-08-31') AS prev_e_rows,
  COUNTIF(action_detail_number = 0 AND outpatient_date.value BETWEEN DATE '2026-09-01' AND DATE '2026-09-30') AS month_e_rows,
  COUNT(DISTINCT IF(action_detail_number = 0 AND outpatient_date.value BETWEEN DATE '2026-09-01' AND DATE '2026-09-30', outpatient_date.value, NULL)) AS month_e_days
FROM `medup-foro.dpc_patient_records_prd.outpatient_ef`
WHERE tenant_id = 11
  AND data_type != 'SY';
```

最大受診日が対象月末以降で、対象月の E行が前月と同じ桁、受診日が月の日数ぶんあることを確認する。無ければ CS 経由で要求する。

2026-10-21 時点: 最大受診日は 2026-08-31、9月の E行は 0（`Eg_438211911_2608.txt`）。10月実行分（対象月末 2026-09-30）はここで止めている。

## 2. 予約CSVを置く

手順1で見た予約月のファイルを `data/11/` に置く。

- `外来予約情報YYYYMM.csv`（泌尿器科・呼吸器外科の両方で使う）
- `手術予約情報YYYYMM.csv`（泌尿器科のみ）

文字コードは cp932。ファイル名の月と中身を揃える。202609 と 202610 は別抽出で、行数が違うと結果件数も変わる。

## 3. yaml のパスと期間を更新する

- `src/pipeline/tenants/t011/urology.yaml`
- `src/pipeline/tenants/t011/respiratory_surgery.yaml`

両方の `appointment_csv` を置いた外来予約ファイルにする。泌尿器科は `surgery_csv` も更新する。`start_date` / `end_date` は、手順1で揃っていた対象月までの直近12か月にする。2026-09 に実行するなら `2025-09-01` から `2026-08-31`。2026-10 に実行するなら `2025-10-01` から `2026-09-30`。

## 4. 実行する

`~/ws/outpatient-ops` で、泌尿器科から実行する。

```bash
uv run python -m src.pipeline.tenants.t011.urology
uv run python -m src.pipeline.tenants.t011.respiratory_surgery
```

BigQuery の認証が切れていたら、先に `gcloud auth application-default login` する。

## ローカルに入っている修正

未コミットのまま残している。次回もこの作業ツリーで実行する。

- 医師マスタは `sk-kumamoto_doctor_master_snapshot`（アンダースコア）。Notion にあるハイフン付きの名前は存在しない。元の外部テーブルは Drive 権限がなく読めない。
- 患者サマリーと紹介データの DataFrame 化は `infer_schema_length=None`。先頭行の日付が空だと、並び順によっては Polars が落ちる。件数は変わらない。

呼吸器外科の対象医師コードは 2件 / 3名のことがある。マスタに名前が一致しない医師がいる。予約枠の出力には名前が残る。
